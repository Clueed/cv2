## Cover letter — verbatim content of `cover-letter/data.typ`

- **Recipient**: Gian Caprini, Nuitée, Barcelona / Remote EU
- **Date**: June 28, 2026
- **Subject**: Application: GTM Engineer
- **Salutation**: Dear Gian,

> As AI collapses the cost of generating an interface, the interface stops being the moat. Front-ends become disposable, generated on demand, and they all resolve down to the same thing: a call to an API. The durable value moves to the layer everything else composes against. That is the layer I want to build on, and it is why Nuitée is the company I am writing to. An API backbone for travel, "Stripe for Travel," is a bet on exactly the part of the stack I think actually matters over the next decade.
>
> The other half of *why this role* is starting "from a mostly blank page". This is not a constraint I would tolerate. It is the thing I am looking for. The part of the work I optimize for is deciding what needs to exist and building it before anyone hands me structure.
>
> What a blank page really tests is balance: not months of systems-building in a vacuum, not getting buried in day-to-day operations, but knowing which the moment needs. At Stackgini I lived both sides, running the operational sales by hand while building the systems that scaled past that work. The building is the side I want to move toward now, because I would rather make the organisation 5% better than myself 20% better: less hand-selling, more system design, more room to go deeper on the engineering.
>
> AI is not a feature of the systems I build. It runs through everything I do. It is still a leaky abstraction today: it breaks in ways you only catch if you understand what sits underneath, so using it well is an engineering problem, not a prompting trick. My computer science background lets me judge where it fits and build against it from first principles, fast. That holds at every scale of my work, from inferring whether a prospect is a Mr or a Ms for an email salutation, to custom harnesses that let an agent prospect a company on its own, to the Claude Code workspaces I build to run most of my day-to-day.
>
> I would welcome a conversation about how I would approach the first version of this machine at Nuitée and which signals I would instrument first.

Sign-off: Best regards, Mark Vavulov.

### Cover-letter structure (four-beat thesis + close)

1. **Why-Nuitée = the API-as-durable-layer thesis.** Opens on a first-principles argument that AI commoditizes interfaces and the durable value is the API layer everything composes against, landing on "Stripe for Travel" as a bet on the right part of the stack. This is the why-company hook, framed on conviction about the architecture rather than the travel domain (zero reps, deliberately not claimed).
2. **Why-this-role = the blank page is the draw, not a tolerated cost.** Directly answers the JD's "from a mostly blank page" framing; positions building-before-structure as what Mark optimizes for.
3. **The balance claim = lived both sides at Stackgini.** Operated sales by hand *and* built the systems that scaled past that work; states the directional preference ("make the organisation 5% better than myself 20% better: less hand-selling, more system design") — the line the role-fork note warns cuts against the Product GTM Manager seat.
4. **AI as engineering, not prompting.** The load-bearing differentiator: AI runs through everything, it is a leaky abstraction, using it well is an engineering problem the CS background equips him for. Three concrete artifacts span the scale ladder: Mr/Ms salutation inference → autonomous company-prospecting agent → the Claude Code workspaces that run his day-to-day.
5. **Close**: a direct, non-hedged ask to discuss how he'd approach the first version of the machine and which signals he'd instrument first (echoes the JD's track→score→route→convert remit).

## What this package deliberately does NOT do

- **No travel-domain claims.** Mark has zero travel reps; the why-company is built on the API-layer architecture thesis, not feigned travel-industry expertise.
- **No PLG-rep fabrication.** The CV/letter never claim product-led-growth or product-analytics experience Mark lacks. The bridge is honest systems-transfer (a scoring/routing system generalizes; the inputs change), per [[feedback_no_self_hedging]].
- **No demand-gen / marketing-lexicon padding.** Engineer-seller / builder vocabulary throughout, matching the JD's filter.
- **No Product GTM Manager framing.** This package commits to the GTM Engineer (Gian / VP Growth) seat; the closing-heavy positioning the sibling role wants is intentionally downplayed (see the role-fork note).
- **Stack name-drop kept honest.** Mark's verbatim daily stack (HubSpot, Apollo, Lusha, Instantly, Claude, raw LLM APIs) surfaces; the JD's heavier data stack (PostHog, BigQuery, Looker Studio) is NOT claimed as held experience — those are the new reps flagged in [[references/nuitee-gtm-engineer-jd]].
